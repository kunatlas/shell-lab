# ShellLab · Shell 练习室

在真实 Linux Bash 里练习命令和脚本。网页通过 WebSocket 与 PTY 传递终端输入、输出，命令直接交给 Bash 执行。不会模拟命令、改写报错，或要求输入唯一的标准答案。

支持按 Linux 后端开发场景动态出题：随机生成初始数据、筛选条件和任务组合，每道题都先在独立工作区执行参考解并验证判题，再交给你练习。支持参考提示、逐项目标检查、浏览器实战完成记录和环境重置。

## 后端开发动态实战

点击左侧 **“场景库”** 展开开发场景。点击具体场景可以开始专项练习，或点击 **“生成开发实战”**，选择出题范围和难度，再点击 **“生成并开始”**。基础专项生成 1 个场景，组合实战最多 2 个，综合挑战最多 3 个；所选场景少于上限时使用实际可用数量。不选范围时从全部可用场景中随机组合。选择并生成前不会自动创建练习会话。

**“重置环境”恢复同一道题的初始状态，“换一道题”重新生成数据与任务。** 刷新页面会恢复当前题目和 Shell 会话；生成失败保留原环境。每次生成前会检测所需工具，缺少工具的场景会在选择器里显示原因。本机模式不会擅自安装 Git、Python、curl 等系统工具。

左侧场景按“排查与诊断 / 文件与数据 / 发布与工程 / SSH 与远程”分组，可折叠；筛选框支持按名称、描述、概念和工具搜索，按 `/` 可快速聚焦。按 `⌘K`（Windows/Linux 为 `Ctrl K`）打开命令面板，可直接跳转场景或执行“生成开发实战 / 命令速查 / 重置环境”等操作。场景库在桌面和移动端均以抽屉打开，支持遮罩和 Esc 关闭。练习区支持终端展开 / 收起、`Ctrl+Enter`（macOS 为 `⌘Enter`）检查结果；左侧“历史”查看本机完成记录，“设置”可调整并保存终端字号。

出题不是只替换文件名：日志题会改变查询目标和聚合条件，清理题会改变时间/大小约束，数据题会在汇总与去重之间变化，不同场景还能组合成一次值班演练。不过它仍以受验证的能力目录为边界，并不承诺无限创造新的题型。

HTTP 服务只监听练习环境的回环地址和随机端口，不访问外网。进程题只启动专属 Python worker。临时验证环境、重置前的环境以及服务关闭时的环境都会清理对应服务和进程。

网络排查题使用真实的 HTTP 服务和 curl：服务按 Host 区分请求，直接访问 IP 会返回 404；可以用 `--resolve` 将题目中的 `.test` 域名临时映射到回环地址，不修改系统 DNS 或 hosts。端口题用 `ss` 观察实际监听套接字及其进程。磁盘题在任务目录创建小体量真实数据，`du` 的结果按当前文件系统实际占用验证，不预设某种块大小。

可靠脚本题会用新的输入反复运行脚本：重试题检查先失败后成功、耗尽次数和真实超时；安全写入题注入半成品失败，检查正式文件和临时文件清理；互斥题由另一个进程实际持有文件锁，检查是否立即返回 75，释放后能否再次执行。它们对应接口探测、发布产物和定时备份中常见的脚本行为，不需要改动系统 cron。

## SSH / SCP 实战

现在共有 **25 类开发场景**。SSH/SCP 的 5 类实战使用真正的 **OpenSSH sshd、ssh、scp 和 SFTP 服务端**。每道题都会启动独立服务，创建一次性的客户端密钥和主机密钥，生成专属 `known_hosts`，并使用随机回环端口。服务只接受密钥认证，不修改 `/etc/ssh`、个人 `~/.ssh` 或系统账号。

题目中的 `connection.txt` / `connection.env` 给出实际用户、地址、端口、密钥路径与专属远端目录；`client.conf` 是预置的 `lab-target` 客户端配置。主机别名题要求另写 `ssh_config`。远端命令在这道题的 `remote` 目录中开始执行；本机模式仍使用当前系统账号和权限，不提供文件系统隔离，Docker 模式则在容器内部运行全部服务。

可以单独练习密钥登录、远程退出码、主机别名、双向文件传输和递归传输，也可以选择综合发布流程。SCP 支持默认的 SFTP 传输和 `-O` 旧协议；递归题会检查隐藏文件、带空格文件以及指定文件的权限、修改时间。判题也会检查练习服务确实接受过公钥登录。

本机一键启动时，`start.sh` 会调用 `setup-ssh.sh`：如果系统缺少服务端，会尝试从当前 APT 软件源下载官方 OpenSSH 包，并解包到项目的 `.tools/openssh`，不运行系统安装和服务启停操作。也可以单独运行：

```bash
./setup-ssh.sh
./start.sh
```

项目内工具准备已在 Ubuntu 24.04 的普通用户环境实测。首次准备需要联网；使用拆分式 sshd 辅助程序的新发行版，或非 APT 系统，请通过系统包管理器安装 OpenSSH 客户端、服务端和 SFTP 服务端，或使用 Docker 模式。准备失败时其他场景仍能使用，SSH 场景会显示缺少工具的原因。自定义工具路径可在 `.env` 配置 `SHELL_LAB_SSHD`、`SHELL_LAB_SFTP_SERVER` 和可选的 `SHELL_LAB_SSH_LIB_DIR`。

重置同题会重新生成连接端口和密钥，因此需要重新读取连接信息。生成参考解所用的临时服务会先清理，再创建交给用户的初始环境；重置、环境回收和正常关闭服务时也会清理 sshd 及其会话。

## 可选：AI 场景规划

未配置模型时，**本地动态出题可以直接使用**。如果需要模型按工作情境选择和组合任务，在 `.env` 中配置支持 Chat Completions 的服务：

```dotenv
SHELL_LAB_AI_BASE_URL=https://你的服务地址/v1
SHELL_LAB_AI_MODEL=你的模型名称
SHELL_LAB_AI_API_KEY=你的密钥
```

重启后在出题弹窗选择 **“AI 场景规划”**，填写偏好，例如“上线后接口变慢，想练日志排查和配置回滚”。可使用云端服务或兼容的本地模型服务；本地服务无需密钥时可以不设置 `SHELL_LAB_AI_API_KEY`。默认使用 JSON Schema 结构化输出，不支持该格式的服务可设置 `SHELL_LAB_AI_JSON_MODE=object`，返回内容仍须通过服务端校验。格式参考 [OpenAI 官方结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)。

AI 只负责在所选范围内规划场景顺序、标题和背景；数据、具体目标、初始化及判题由程序生成。不会执行 AI 生成的 Shell 代码，也不会把 AI 描述当作判题条件。发送给模型的内容是场景目录、难度和你输入的偏好，不包含终端输出或本机文件。密钥只在后端使用，不返回浏览器。

这版 AI 接入包含协议和错误处理测试，但没有使用实际云端密钥进行联调。模型服务的可用性、费用和结构化输出支持由你配置的服务决定。

## 一键启动本机模式

在安装了 Node.js **22.12+**（包含 npm）的 Linux 或 WSL2 中执行：

```bash
./start.sh
```

脚本会自动进入项目目录、检查运行环境、安装缺失或需要更新的依赖、准备 SSH 练习工具，并启动本机模式。首次安装需要联网。不需要手动设置环境变量，也不需要先运行 `npm ci`。

启动后打开 **http://127.0.0.1:5173**，停止时按 `Ctrl+C`。也可以在任意目录执行 `bash /你的路径/shell-lab/start.sh`。

本机模式没有隔离，命令以你的系统用户执行，可访问本机文件。需要独立练习环境时，请使用下面的 Docker 模式。

## 启动：独立 Linux 容器

需要 Node.js **22.12+**、npm 和可用的 Docker Engine / Docker Desktop。推荐在 Linux 上开发。macOS 可以通过 Docker 运行 Linux 环境；Windows 请在 WSL2 中运行项目。

```bash
npm ci
npm run sandbox:build
npm run dev
```

打开 **http://127.0.0.1:5173**。开发服务器会把 `/api` HTTP 与 WebSocket 请求代理到 `127.0.0.1:3001`。

默认镜像为 `shell-lab-sandbox:1`，基于 Ubuntu 24.04，包含真实的 Bash、GNU 命令工具、nano、less、tree。语言固定为 `C.UTF-8`，错误消息显示为英文。首次构建镜像需要访问 Ubuntu 软件源。

动态实战还包含 Git、curl、jq、Python、tar/gzip、iproute2、util-linux（含 flock）和 OpenSSH 客户端/服务端。此前已经构建过旧镜像的机器，请重新运行 `npm run sandbox:build` 以安装这些工具。

每个浏览器会话拥有独立容器，重置和切换练习都会创建新环境。网页刷新、WebSocket 断线不会立即销毁 Shell，因此当前目录、变量和文件可以继续使用。30 分钟没有终端输入、连接或判题操作后，环境会被回收。最多同时保留 8 个练习环境。

## 当前机器没有 Docker 时

在**可信的单用户 Linux 开发机**上，可以显式选择本机 Bash 模式：

```bash
SHELL_LAB_RUNTIME=local npm run dev
```

这仍然是真实 Bash，但**没有隔离**：命令以你的系统用户运行，可访问本机文件、网络和进程。临时目录只是练习的起始位置，不是沙箱。界面会持续显示“本机开发环境 · 未隔离”。请使用 Docker 模式练习任意命令。

也可以复制 `.env.example` 为 `.env`，修改配置后启动。`dev` 和 `start` 都会读取 `.env`，已设置的环境变量优先。

## Electron 桌面窗口

安装依赖后，可在带图形桌面的 Linux 中启动桌面版（默认使用 Docker 练习环境）：

```bash
npm ci
npm run sandbox:build
npm run desktop
```

在可信的单用户开发机使用现有本机 Bash 环境：

```bash
SHELL_LAB_RUNTIME=local npm run desktop
```

启动器先构建前后端，再使用系统 Node.js 启动本机后端，等待服务就绪后打开 Electron；关闭窗口时清理服务、PTY 和练习环境。后端单独运行，保持现有 `node-pty` 的 Node ABI，无需为 Electron 重编译。桌面版默认使用 `127.0.0.1:3002`，与 Web 版端口分开；可用 `SHELL_LAB_DESKTOP_PORT` 修改。固定端口使完成记录和字号设置在桌面版重启后保留。桌面版与浏览器的历史记录各自保存。

窗口提供可拖动标题栏、最小化、最大化 / 还原和关闭。主进程、preload 和渲染层分离，渲染器启用 sandbox 与 context isolation，仅通过白名单 IPC 控制窗口和写入剪贴板（渲染层仍拒绝读取剪贴板等权限请求）。当前提供从源码启动，尚未制作安装包；练习后端沿用 Linux / Docker 的要求。

首次启动时 Electron 会下载对应平台的二进制文件，需要联网。桌面集成验证可以执行 `npm run test:desktop`（需要可用的图形显示环境；无桌面环境时使用 `xvfb-run -a npm run test:desktop`）。

## 环境一致性的范围

Shell 解析、变量展开、引号、管道、重定向、退出码、命令历史、Tab 补全和 Ctrl+C 由真实 Bash、工具和终端处理。每个练习使用一个持续运行的 Shell，判题则通过独立进程读取文件或运行脚本，不会注入命令打断交互。

默认容器使用固定的发行版系列和语言设置。Ubuntu 镜像及软件包会收到更新，因此尚未承诺跨时间的字节级输出复现；需要这种保证时应固定基础镜像 digest 和软件包版本。`SHELL_LAB_IMAGE` 指向自定义镜像时，界面的默认 Ubuntu 标签也需要相应调整。

这不是完整虚拟机：内核来自 Docker 的 Linux 主机；以普通用户运行，外部网络关闭，系统目录只读，只开放临时家目录与 `/tmp`，并限制内存、CPU、进程数和可写存储。回环网络可用于真实 HTTP 和 SSH/SCP 场景。涉及 root、内核、设备、外网主机、完整 systemd/Docker 运维或实际数据库服务的操作不属于这版练习范围。文件操作与脚本练习中的结果，以该容器内直接执行的结果为准。

本机开发模式则使用主机的 Bash、工具版本和系统权限，不能用来验证 Ubuntu 镜像的一致性。

## 验证

```bash
# 类型检查、前端构建、后端编译
npm run build

# 真实 Bash / PTY、判题、重置、HTTP 与 WebSocket 集成测试
./setup-ssh.sh
npm test

# 在有 Docker 的机器验证实际容器、动态场景和权限隔离
npm run sandbox:build
npm run test:docker

# 浏览器中的真实终端操作、提示、判题、重置和手机布局
npx playwright install chromium --only-shell
npm run test:browser

# Electron 窗口、主进程 IPC、剪贴板与启动器清理
npm run test:desktop
```

`npm test` 显式使用临时目录中的本机 Bash 运行固定测试命令；它不会自动启用服务器的本机模式。缺少 OpenSSH 服务端时，SSH 测试会明确跳过；先执行 `setup-ssh.sh` 可以运行完整验证。Docker 测试默认跳过，只有 `test:docker` 才会运行。浏览器测试需要先完成构建并准备 SSH 工具，会自动在本机 Bash 模式启动测试服务，运行前请关闭占用 3001 端口的开发服务。Linux 缺少浏览器依赖时可运行 `npx playwright install --with-deps chromium --only-shell`。

GitHub Actions 配置包含构建、Bash 集成测试、真实 Docker 测试和浏览器测试。

## 代码结构

```text
electron/               Electron 主进程、受限 preload 和独立后端入口
scripts/desktop.mjs     桌面启动与进程清理
src/ui/                 界面壳层、图标和桌面桥接
src/                    TypeScript 页面、xterm.js 终端与样式
shared/types.ts         前后端数据类型
server/app.ts           HTTP、Cookie 会话和 WebSocket 接口
server/runtime.ts       Docker 与本机 Bash / PTY 适配器
server/sessions.ts      连续会话、输出缓存、判题和回收
server/exercises.ts     动态题目与练习服务的数据类型
server/generator/       场景目录、随机任务组合、AI 规划与可解性验证
server/fixtures.ts      真实本地 HTTP 服务与 worker
server/ssh-fixture.ts   专属 OpenSSH 服务、临时密钥和远端家目录
server/ssh-tools.ts     系统或项目内 SSH 工具的发现
setup-ssh.sh           本机 SSH 工具准备（无系统安装）
sandbox/                Linux 镜像和统一 Bash 提示符
tests/                  Bash、API、Docker 与浏览器测试
```

增加动态场景时，在 `server/generator/catalog.ts` 注册工具与能力，在 `builders.ts` 实现初始数据、目标检查、提示和参考解。新题必须先验证初始状态未通过全部目标，再验证参考解能通过所有检查；验证后的环境会销毁，用户获得全新的初始环境。

每个目标的 ID 需要一致。检查通过退出码判断，0 为通过。脚本题的判题会运行用户写的脚本，每个目标最多执行 3 秒；检查可能创建或修改练习文件。生成器完整参考解的试做上限为 15 秒，以容纳多场景 SSH 握手；单项目标的 3 秒限制保持不变。相同随机种子和配置可以复现题目数据；服务端口、SSH 密钥和进程 PID 则由每次新建的真实运行环境决定。

完成进度仅记录在当前浏览器的 localStorage 中，不是账户成绩。练习文件和 Shell 会话没有长期持久化。
